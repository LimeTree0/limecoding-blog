# 결정 및 검토 기록

기준일: 2026-11-08

이 문서는 사용자가 표현한 방향과 AI의 제안을 구분한다. 저장소 생성·설정·구현이 완료되었다는 의미는 아니다.

## 사용자 의사로 확인된 방향

| 항목 | 내용 | 배경 |
| --- | --- | --- |
| 프로젝트 | 개인 기술 블로그를 만들고 GitHub 저장소를 준비한다 | 직접 운영할 블로그가 필요함 |
| 개발 경험 | React로 직접 개발하고 싶다 | 구현하는 재미도 중요함 |
| 지식 연결 | 글을 타고 이동하며 탐색할 수 있는 경험을 원한다 | 일회성 글 소비를 넘어 축적된 내용을 활용하고 싶음 |
| 확장 관심 | 문서 그래프와 AI를 이용한 내용 소개·탐색을 고려한다 | 옵시디언과 같은 연결 탐색에 관심 |
| 비용 방향 | 운영 비용을 작게 유지하고 싶다 | 정적 배포만으로도 충분할 수 있다고 판단 |
| 기록 목적 | 컨셉과 결정 이유를 나중에 돌아보기 위해 남긴다 | 공개 발표보다 개인적인 의사결정 기록이 주목적 |
| 기존 목업 평가 | 전반적으로 긍정적이며 검색 UI 등은 수정 가능 | 완전한 최종 디자인 확정은 아님 |

## 제안된 사항: 아직 확정 아님

| 항목 | 제안 | 이유 |
| --- | --- | --- |
| 저장소 이름 | `limecoding-blog` | 브랜드와 용도가 드러남 |
| 저장소 설명 | 호기심으로 탐구하고 지식을 연결하는 개인 기술 블로그 | 서비스 방향을 간단히 표현 |
| 문서 위치 | 저장소의 `docs/` | 소스 변경과 함께 기록 관리 |
| Codex 인수인계 | `AGENTS.md`에서 배경 문서를 안내 | 다른 작업 세션에서도 맥락 파악 |
| 초기 운영 | 정적 배포와 파일 기반 콘텐츠 우선 검토 | 비용과 관리 부담 절감 |
| 공개 설정 | 소스 공개가 괜찮으면 Public | 공개 의사는 최종 확인 필요 |
| 코드 라이선스 | 재사용을 허용하려면 MIT 검토 | 글·이미지 이용 조건은 별도로 결정 |

## 아직 정하지 않은 사항

- 저장소 최종 이름, 공개 여부와 라이선스
- 콘텐츠와 컴포넌트의 구체적인 파일 구성 및 작성 규칙
- 본문 이미지 관리와 콘텐츠 운영 규칙의 확장
- 배포 서비스, 도메인과 운영 예산
- 검색·그래프 등 후속 화면의 최종 구성과 동작
- 검색 UI와 검색 구현 방식
- 태그·카테고리·글 관계 모델
- 초기 출시 범위와 완료 기준
- 그래프와 AI 기능의 도입 시점 및 구체적인 동작

## 이후 기록 방법

### 2026-11-08 — 최소 글 흐름 이후 Figma 디자인 적용

- 상태: 확정 (사용자 요청), 구현 세부사항은 아래에 구분
- 결정: 샘플 MDX 2개의 목록·상세 흐름을 먼저 만든 뒤 공통 스타일, 헤더·홈, 글 상세 순서로 기존 시안을 적용한다. 검색과 그래프는 후속 단계로 둔다.
- 이유: 실제 제목, 긴 본문, 코드와 이미지가 표시되는 상태에서 디자인을 검토하려는 사용자 의도다. 콘텐츠 기능 전체를 먼저 완성하는 순서가 아니다.
- 디자인 기준: [Figma 페이지 시안](https://www.figma.com/design/ZIOm3EmlKgInZAW7jZlJZn/limecoding-blog?node-id=3-55)의 `Pages / Desktop & Mobile` 홈·글 목록·상세 화면을 확인했다.
- 구현: 기존 Astro/MDX 컬렉션과 CSS 구조를 유지하고 원본 SVG를 `public/images/design/`에 저장했다. 실제 글 메타데이터와 본문을 사용하며 목차는 MDX 제목에서 생성한다.
- 구현 판단: 글 목록의 관심사 링크는 태그 필터에 연결하고, 소개는 홈 소개로 연결했다. 검색·그래프는 비활성 상태로 표시한다. 홈의 읽기 경로는 기존 두 글의 내부 링크에 맞췄다. 별도 소개·그래프·읽기 경로 페이지는 추가하지 않았다.
- 글꼴: 시안의 Noto Sans KR, Noto Serif KR, JetBrains Mono를 Google Fonts에서 불러온다. 원격 글꼴 요청이 실패하면 시스템 대체 글꼴을 사용한다.
- 접근성 보정: 작은 보조 텍스트는 원본 `#738071` 대신 대비를 높인 `#647160`을 사용한다. 모바일 목차는 화면과 키보드 이동 순서가 일치하도록 본문보다 앞에 배치한다.
- 영향: 새 런타임 의존성이나 서버·DB를 추가하지 않는다. 모바일에서는 목록 썸네일과 보조 영역을 감추고 목차를 본문 위에 표시한다.

### 2026-11-08 — Astro 초기 설정 반영

- 상태: 확정 (사용자의 설정 완료 안내와 저장소 파일 확인)
- 결정: 저장소 루트에서 Astro와 npm을 사용하며 React·MDX 연동과 TypeScript strict 설정을 적용했다.
- 버전: `package.json` 기준 Astro `^7.4.7`, React `^19.3.1`, `@astrojs/react` `^7.1.4`, `@astrojs/mdx` `^8.1.3`. Node.js 요구 버전은 `>=22.23.4`이며 의존성 해석 결과는 `package-lock.json`으로 관리한다.
- 이유: 사용자가 Astro 초기 설정을 완료했다. React를 직접 사용하고 싶다는 기존 방향과 연결되며, Astro를 선택한 구체적인 비교 근거는 별도로 기록되지 않았다.
- 영향: 개발·빌드는 루트의 npm 스크립트를 사용한다. 콘텐츠 운영 방식, 배포 환경, 린트·테스트·CI 도구는 아직 확정하지 않았다.

주요 결정이 합의되면 다음 내용을 추가한다.

```markdown
### YYYY-MM-DD — 결정 제목
- 상태: 제안 / 확정 / 변경 / 보류
- 결정: 무엇을 선택했는지
- 이유: 어떤 요구사항과 제약 때문에 선택했는지
- 대안: 검토한 다른 선택지와 선택하지 않은 이유
- 영향: 기능·운영·구현에 미치는 영향
```

AI 제안에 대한 응답이 없었다는 이유만으로 확정 상태로 변경하지 않는다.
